# Behavioral Design Patterns — Map

```text
Strategy
→ HOW should behavior/algorithm execute?

Observer
→ WHO should be notified when something changes?

Command
→ WHAT ACTION/request should execute?

State
→ HOW does behavior change with current state?

Chain of Responsibility
→ WHO IN THE CHAIN should process, reject, or pass the request?

Template Method
→ WHICH STEPS of a FIXED WORKFLOW should subclasses customize?

Iterator
→ HOW do I TRAVERSE elements without exposing storage?
```

| Pattern | Core Idea |
|---|---|
| Strategy | Interchangeable algorithm |
| Observer | One-to-many event notification |
| Command | Request/action as an object |
| State | Lifecycle-dependent behavior |
| Chain of Responsibility | Sequential request handlers |
| Template Method | Fixed inherited workflow with customizable steps |
| Iterator | Encapsulated traversal |

```text
Strategy = HOW
Observer = WHO GETS NOTIFIED
Command = WHAT ACTION
State = HOW BEHAVIOR CHANGES WITH STATE
CoR = WHO IN THE CHAIN
Template Method = WHICH STEPS OF FIXED WORKFLOW
Iterator = HOW TO TRAVERSE WITHOUT EXPOSING STORAGE
```
